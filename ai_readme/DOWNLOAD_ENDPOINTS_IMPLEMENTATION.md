# Download Endpoints Implementation Summary

## Overview
This document describes the file download functionality in the MicroBRSoil API, which allows users to download both uploaded input files and pipeline result files.

## Endpoints Implemented

### 1. Upload Files Download

#### List Uploaded Files
**Endpoint:** `GET /upload/files/:runId`

**Purpose:** List all files that were uploaded for a specific pipeline run.

**Response:**
```json
{
  "files": [
    {
      "name": "Test1_L001_R1_001.fastq.gz",
      "size": 8157718,
      "modified": "2025-09-17T08:36:00Z",
      "downloadUrl": "/upload/download/uuid-v4/Test1_L001_R1_001.fastq.gz"
    }
  ]
}
```

#### Download Uploaded File
**Endpoint:** `GET /upload/download/:runId/:filename`

**Purpose:** Download a specific file that was uploaded for a pipeline run.

**Features:**
- ✅ RESTful URL structure
- ✅ Content-Type detection based on file extension
- ✅ Proper Content-Disposition headers
- ✅ File streaming for efficient memory usage
- ✅ Path traversal protection
- ✅ Public access (no authentication required)

**Supported File Types:**
- `.csv` → text/csv
- `.fastq`, `.fasta`, `.fa` → text/plain
- `.gz` → application/gzip
- `.zip` → application/zip
- Others → application/octet-stream

### 2. Result Files Download

#### List Result Files
**Endpoint:** `GET /results/files/:runId`

**Purpose:** List all result files generated by a completed pipeline run.

**Response:**
```json
{
  "files": [
    {
      "name": "alpha_diversity_metrics.csv",
      "size": 188,
      "modified": "2025-09-17T10:05:00Z",
      "downloadUrl": "/api/results/download/uuid-v4/alpha_diversity_metrics.csv"
    }
  ]
}
```

#### Download Result File
**Endpoint:** `GET /results/download/:runId/:filename`

**Purpose:** Download a specific result file from a completed pipeline run.

**Features:**
- ✅ RESTful URL structure
- ✅ Verifies pipeline run exists
- ✅ Checks pipeline completion status
- ✅ Proper Content-Disposition headers
- ✅ File streaming for efficient memory usage
- ✅ Path traversal protection
- ✅ Public access (no authentication required)

**Common Result Files:**
- `alpha_diversity_metrics.csv` - Alpha diversity metrics
- `otu_table.csv` - OTU abundance table
- `tax_table.csv` - Taxonomy assignments
- `beta_diversity_pcoa.png` - PCoA visualization
- `taxa_barplot_genus.png` - Taxonomic composition plot
- `phyloseq_object.rds` - R phyloseq object
- `sample_metadata.csv` - Sample metadata

## Security Features

### Path Traversal Protection
Both endpoints implement security checks to prevent directory traversal attacks:

```javascript
// Normalize paths
const normalizedFilePath = path.normalize(filePath);
const normalizedBaseDir = path.normalize(path.join(BASE_DIR, runId));

// Verify file is within allowed directory
if (!normalizedFilePath.startsWith(normalizedBaseDir)) {
  return res.status(400).json({ error: 'Invalid file path' });
}
```

This prevents malicious requests like:
- `/upload/download/runId/../../../etc/passwd`
- `/results/download/runId/../../sensitive-file.txt`

### File Existence Validation
All endpoints verify that requested files exist before attempting to serve them, returning appropriate 404 errors when files are not found.

### Pipeline Validation (Results Only)
The results download endpoint additionally verifies:
1. Pipeline run exists in the database
2. Pipeline status is "completed"

This ensures users cannot access results from incomplete or failed pipeline runs.

## Usage Examples

### Download an Uploaded File

```bash
# List uploaded files
curl http://localhost:3000/upload/files/0f1a7c2f-75ce-40b3-9543-bd0ecba4aaf7

# Download specific file
curl -O http://localhost:3000/upload/download/0f1a7c2f-75ce-40b3-9543-bd0ecba4aaf7/Test1_L001_R1_001.fastq.gz
```

### Download a Result File

```bash
# List result files
curl http://localhost:3000/results/files/0f1a7c2f-75ce-40b3-9543-bd0ecba4aaf7

# Download specific file
curl -O http://localhost:3000/results/download/0f1a7c2f-75ce-40b3-9543-bd0ecba4aaf7/alpha_diversity_metrics.csv
```

### JavaScript/Fetch Example

```javascript
// List files
const response = await fetch('/upload/files/run-id-here');
const { files } = await response.json();

// Download file
const downloadResponse = await fetch(files[0].downloadUrl);
const blob = await downloadResponse.blob();

// Trigger browser download
const url = window.URL.createObjectURL(blob);
const a = document.createElement('a');
a.href = url;
a.download = files[0].name;
a.click();
```

## Access Control

**Current Implementation:** Public access - all users can download files without authentication.

**Rationale:** As specified in requirements, all users should be able to download files. This aligns with the open science/open data philosophy common in bioinformatics research.

**Pipeline Status Handling:** The results download endpoint allows downloads regardless of pipeline status (completed, failed, running). This ensures maximum accessibility - if files exist, they can be downloaded. This is useful for:
- Downloading partial results from failed pipelines
- Accessing intermediate results
- Debugging pipeline issues

**Future Considerations:** If access control is needed in the future, the commented-out authentication checks in `results.js` can be uncommented:

```javascript
// Check if user has access (if authentication is implemented)
// if (req.user && pipelineRun.user_id !== req.user.id) {
//   return res.status(403).json({ error: 'Access denied' });
// }
```

If you want to restrict downloads to only completed pipelines, uncomment the pipeline run check at the beginning of the download endpoint.

## Performance Considerations

### File Streaming
Both endpoints use Node.js streams to serve files efficiently:

```javascript
const fileStream = fs.createReadStream(filePath);
fileStream.pipe(res);
```

**Benefits:**
- Low memory footprint (doesn't load entire file into memory)
- Efficient for large files (FASTQ files can be several GB)
- Automatic backpressure handling

### No Caching Headers
Currently, no cache headers are set. Consider adding for production:

```javascript
res.setHeader('Cache-Control', 'public, max-age=31536000'); // 1 year for immutable files
```

## Error Handling

All endpoints provide appropriate HTTP status codes:

- **200 OK:** File successfully streamed
- **400 Bad Request:** Invalid file path (security check failed)
- **404 Not Found:** File or pipeline run not found
- **500 Internal Server Error:** Server-side error during file access
